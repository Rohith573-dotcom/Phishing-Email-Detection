A **defensive** e-mail classifier that separates phishing from legitimate mail using two
complementary channels:

- **Linguistic** — manual tokenisation, stop-word removal, stemming, TF-IDF over unigrams
  and bigrams of subject + body.
- **Structural** — 17 interpretable metadata features describing the links, the sender
  anatomy and the pressure tactics of each message.

Four classifiers are implemented from scratch in NumPy and each is trained on three
feature views, which answers the central question of the comparative report: **how much
does structure add on top of wording?**

## Results

Held-out stratified 20% test set (501 messages), combined feature view, seed 42.

| Model | Accuracy | Precision | Recall | F1 | ROC AUC | FP | FN | Fit (s) |
|---|---|---|---|---|---|---|---|---|
| **Logistic Regression** | **0.9222** | 0.9363 | 0.9109 | **0.9234** | 0.9688 | 16 | 23 | 2.74 |
| Naive Bayes | 0.9202 | 0.9225 | 0.9225 | 0.9225 | 0.9691 | 20 | 20 | 0.01 |
| Random Forest | 0.9062 | 0.9237 | 0.8915 | 0.9073 | 0.9684 | 19 | 28 | 12.42 |
| Neural Network | 0.9142 | 0.9249 | 0.9070 | 0.9159 | 0.9598 | 19 | 24 | 3.66 |

FP = legitimate mail quarantined · FN = phishing delivered to the inbox

5-fold cross-validated F1: **0.9148 ± 0.0084**

### Ablation — the headline result

F1 by feature channel:

| Model | Text only | Metadata only | Text + Metadata |
|---|---|---|---|
| Logistic Regression | 0.9080 | 0.9055 | **0.9234** |
| Naive Bayes | 0.8998 | 0.8828 | **0.9225** |
| Random Forest | 0.8880 | 0.8975 | **0.9073** |
| Neural Network | 0.8976 | 0.8958 | **0.9159** |

**17 structural features come within a quarter of a point of 1,200 TF-IDF terms** (0.9055 vs 0.9080 for logistic regression). Phishing has a characteristic *shape*, not only a characteristic vocabulary. And the two channels **combine well** — using both lifts logistic regression to 0.9234. A lure has to say something urgent *and* carry a link, and those two obligations leave separate traces.

> **Calibration note.** The generator's mixture parameters are set so accuracy lands in the low
> nineties, the band production filters report on real mail. An earlier, harsher setting held every
> model in the mid-eighties. Both are one edit apart in `generate_sample_dataset.py`, and the model
> ranking is *not* stable across them. Since we wrote the generator we also chose the difficulty, so
> these percentages measure the pipeline rather than the threat.

## Using a real corpus

The bundled corpus is **synthetic**. To switch to real data, save it as `data/emails.csv`
with `sender`, `subject`, `body` and `label` columns (`0` = legitimate, `1` = phishing),
then re-run `python main.py`. Suitable public sources:

- Kaggle *Phishing Email Detection*
- SpamAssassin public corpus (legitimate mail)
- The Nazario phishing corpus

The loader prefers `data/emails.csv` when present and falls back to the synthetic corpus.

---

## About the bundled dataset

`data/emails_raw.csv` is generated by `generate_sample_dataset.py`. It is synthetic and
defensive in purpose: it reproduces the *surface patterns* a filter must learn to
recognise — manufactured urgency, credential-harvesting calls to action, generic
salutations, look-alike sender domains, raw-IP links — using placeholder brands and
RFC-2606 reserved domains (`example.com`, `example.net`). **Nothing in it is a working
lure and no real organisation is impersonated.**

As in Project 1, each message carries a hidden leaning θ ~ Beta(0.7, 0.7) so the classes
overlap genuinely and the algorithms separate on merit rather than on an artificial
vocabulary split.

Both the raw and the cleaned corpora ship as deliverables:
`data/emails_raw.csv` and `data/emails_clean.csv`.

## The 17 structural features

| Group | Features |
|---|---|
| Link shape | `n_urls`, `has_ip_url`, `n_insecure_urls`, `max_url_path_depth`, `has_html_anchor` |
| Sender anatomy | `sender_domain_hyphens`, `sender_subdomain_depth`, `sender_domain_len`, `sender_is_role_account` |
| Pressure tactics | `n_exclamations`, `subject_caps_ratio`, `subject_urgency_hits`, `body_urgency_hits`, `credential_hits`, `reward_hits`, `generic_greeting`, `body_word_count` |

Min-max scaled rather than z-scored, so multinomial naive Bayes — which requires
non-negative input — can use the same matrix. Scaling is fitted on the training split only.

## Key findings

- **All four models clear 90%**, with under two points between first and last — so the
  ordering itself carries little weight.
- **F1 picks the wrong model.** Logistic regression tops the F1 table but lets through 23
  phishing messages; naive Bayes misses 20, has near-symmetric errors (20 FP / 20 FN), and
  fits in 0.01 s against 12.4 s for the random forest. On the error that actually matters —
  a lure reaching an inbox — naive Bayes is the one to deploy.
- **Seventeen structural features rival the whole vocabulary.** 0.9055 F1 with no lexical
  information at all, against 0.9080 for 1,200 TF-IDF terms. Seventeen numbers an analyst
  can read and check by hand carry within a quarter point of the entire lexicon.
- **The channels combine well.** Both together lift logistic regression to 0.9234, above
  either alone. A lure has to say something urgent *and* has to carry a link, and those two
  obligations leave separate traces.
- **Training cost is a real operational constraint.** A filter retrained on every batch of
  user-reported mail needs to fit in milliseconds, not seconds. On a corpus this size the
  difference sounds trivial; on a live mail flow it is the difference between keeping up and
  falling behind.

## What this does and does not establish

We wrote the generator, so we also chose the difficulty. These percentages measure whether
the pipeline works, not how well it would catch real phishing. What we would defend is the
**structural feature design** and the **ablation result** — that seventeen interpretable
features rival the lexical channel held at every difficulty setting we tried, including the
harsher calibration where every model sat in the mid-eighties.

The robustness argument for keeping the structural channel is separate from its accuracy
contribution. Wording is cheap for an adversary to rewrite; structure is constrained by the
attack itself, since a credential-harvesting campaign needs a link to a host it controls and
a bulk campaign needs a generic salutation. Features anchored to those constraints should
degrade more slowly under adversarial pressure.

## Operating responsibly

- **Quarantine, never auto-delete.** A false positive that silently destroys a legitimate
  message is materially worse than one that delays it, and users must be able to review
  what was held.
- Sender metadata is collected for security triage only, not to profile correspondents.
- Consequential mail warrants a human-review path; the coefficient readout exists to make
  that review possible.
- The decision threshold is a **policy choice about relative harm**, not a modelling
  parameter. Set it deliberately.

## Limitations

- Synthetic corpus; regenerate on a public labelled corpus before citing figures.
- English-only, single stylistic period.
- No authentication headers — SPF, DKIM and DMARC are among the strongest real-world
  signals and are absent here.
- No attachment inspection or URL-reputation lookup.
- A static model decays as campaigns evolve; this evaluation does not measure that drift.
